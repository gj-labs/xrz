# XRZ is not Antigence Clean Room

**Governance decision:** Keep the Samsung XR/S25 demonstration (`gj-labs/xrz`, `biobitworks/xrz`) entirely separate from the established private **Antigence Clean Room** (`biobitworks/antigence`). Both can use familiar source-custody ideas, but their evidence, experiments, operational protocols, ancestry and release decisions are not fungible.

## Project scope

**XRZ:** smartphone/S Pen and Galaxy XR interfaces; protein and therapeutic reference data; independent on-device model comparisons; mock nonhazardous lab procedure guidance; typed FCO/FCG and Merkle/MMR logging **scoped to XRZ**. PPE observations are advisory; approved human SOP is authoritative. XRZ is not an Antigence clean-room deployment or a validation of Antigence's detector performance.

**Antigence Clean Room:** privately governed Antigence anomaly/security/evidence line and its already existing clean-room predecessor/successor branches and receipts. XRZ data, synthetic mock-lab cases, device observations, model results, PR reviews and computed roots **do not enter its canonical state** unless explicitly admitted by its own governance.

## Historical mistake and correction

The fork previously opened [XRZ PR #2](https://github.com/biobitworks/xrz/pull/2), proposing an Antigence/Copilot clean-room protocol as an XRZ successor. **That PR was closed unmerged for scope mismatch.** Its commits/comments remain in historical GitHub custody as a rejected proposal; the branch must not be silently cherry-picked or relabeled as admitted Antigence evidence. Its eight-case synthetic mock-lab fixture is not part of Antigence's already established clean-room experiments.

The only upstream-ready XRZ handoff is [PR #1](https://github.com/biobitworks/xrz/pull/1), sourced from `handoff/mvp-custody-team-20261017`, not the abandoned successor branch.

## Enforced separation rules

- Bind every receipt and breakpoint to its *exact project ID, repository, source commit, task/turn, occurrence context and declared transform identity*. Identical bytes/identical hashes deduplicate content, **not occurrence, reviewer or project identity**.
- No cross-project data, security policy, IP, model weights, Copilot prompts, GitHub Actions receipts, notebook outcomes, root/peak arrays, signing assertions or scientific claims inherited merely because code or terminology overlaps.
- A cross-project reference is at most a **source-cited declared relationship**, not a Merkle inclusion in another project, a new signing claim or evidence of causality.
- To import a dependency, require verified copyright/license and data rights, retained original source bytes/identity and project-specific occurrence, explicit approval by the receiving project's maintainer, independent replay/tests and a successor breakpoint. If any prerequisite is unknown, ABSTAIN.
- No private Antigence inputs in public XRZ and no XRZ experiments inserted into the private Antigence canonical Clean Room ledger.
- GitHub Copilot/other agents must use the repository's own instructions. Treat external agent outputs as proposals until exact source and execution receipts are independently reviewed.
- Corrections are append-only successors; the withdrawn PR and its failure receipts are not rewritten.

## Distinguish safety approvals from source control

XRZ's GitHub maintainer approves *merging source documentation and test software*. An authorized institution approves any use in live BSL-2 workflows. Neither authority can substitute for the other's authorization. Antigence Clean Room has its own independent repository governance.
